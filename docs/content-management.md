# 内容管理

站点的论文、会议、项目、学习经历、荣誉、著作、系统开发、首页动态、追踪卡片，全部存在 `data/content.json`，用一个**跑在本机的网页中台**来改。

```
浏览器（127.0.0.1:4399）── HTTP ──▶ admin/server.mjs ──读写──▶ data/content.json ──构建──▶ 站点
     你在这里编辑                    校验 / 备份 / git / ORCID / BibTeX
```

中台是仓库自带的，只绑定本机回环地址，不对外网开放，也不需要账号或密钥。

---

## 一、启动

```bash
npm run admin
```

浏览器会自动打开 <http://127.0.0.1:4399/>。换端口：

```bash
npm run admin -- --port 4400
```

不加 `--no-open` 时会自动开浏览器；不想让它开就 `npm run admin -- --no-open`。

---

## 二、日常使用

### 改内容

左侧点分区 → 点条目展开 → 直接编辑 → 点右下角的**保存**（或 `⌘S`）。

- 保存前会跑一遍校验，**不通过就不落盘**。
- 落盘前自动留一份快照到 `data/backups/`，出错随时能回滚。
- 双语字段（标题、期刊…）分「中文 / EN」两个输入框，只填一边时另一边自动兜底。
- 作者、标签是回车添加的胶囊；标签可以单独配色。
- **顺序就是站点上的显示顺序**，用条目里的「↑ 上移 / ↓ 下移」调。
- 顶栏的圆点：橙色=有未保存改动，灰色=有未提交改动，绿色=干净。

### 发布

改完保存只写到了本地文件。要上线还差两步，顶栏就能做：

1. **提交** —— 填一句提交信息，并选**提交范围**：
   - **全部改动** —— 源码、样式、博客、数据一起提交。**站点新增功能（新页面、新组件、改了 `App.tsx`）必须选这个。**
   - **仅内容数据** —— 只提交 `data/content.json` 与抓取快照，适合单纯更新了一条论文。
2. **推送** —— 推到 `origin`，GitHub Pages 构建完站点就更新了。

> **最容易踩的坑**：站点源码和内容数据在同一个仓库里。只提交 `data/` 的话，推上去的是
> **「新内容 + 旧代码」**——功能明明写好了，线上却看不到。现在点「推送」时如果工作区还有
> 未提交的文件，中台会先问一次「一起提交并推送 / 只推送已提交的部分」，不要顺手跳过。

推送失败多半是本机网络代理问题，可以在终端里手动 `git push origin main`。

提交之后 GitHub 那边要跑一次构建（约 1 分钟），去看 [Actions](https://github.com/JIAJUN-TANG/JIAJUN-TANG.github.io/actions)
确认是绿的；红了就是构建失败，站点会停在上一版。

### 新增一条

右上角「＋ 新增」。ID 会自动生成（论文 `p9`、项目 `r7`…），也可以手改，只要不重复。

## 三、论文的自动获取

中台里三样东西能省掉大部分手工录入。

### 1. ORCID 同步（推荐）

侧栏 → **ORCID 同步** → 「拉取 ORCID」。

它会拉取你 ORCID 名下的作品，跟站内论文**按 DOI 优先、标题兜底**对号入座，然后分成三堆给你看：

- **可以从 ORCID 补充的字段** —— 逐条列出「现在是什么 → 会变成什么」，你勾哪条就只补哪条。
- **ORCID 上有、站点还没有的作品** —— 勾选即新增为论文。
- **站内有、ORCID 没有** —— 中文刊通常不在 ORCID 里，保持手填内容不动。

规则是**只补空缺、绝不覆盖**你已填的内容。按「应用选中」后直接写回文件，然后照常保存/提交/推送。

ORCID iD 配在 `admin/config.json` 的 `orcidId`，也可以在弹窗里临时改。

### 2. BibTeX 导入

侧栏 → **BibTeX 导入** → 贴 `.bib` 内容 → 「解析」→ 勾选 → 「导入选中」。

从 Google Scholar、Zotero、期刊网站导出的 `.bib` 都能吃：支持嵌套花括号（`{Deep}`）、`\textit{}` 之类的 LaTeX 命令、`Tang, Jiajun` 这种姓在前的中文/英文作者名会自动转成 `Jiajun Tang`。

导入时按 **DOI → 标题**自动去重，已经有的会被跳过而不是插重复。

### 3. Google Scholar 引用同步

侧栏 → **引用同步** → 「立即同步」。

它跑一次 `scripts/update_scholar_citations.py`，把每篇的引用数写进 `data/scholar.json`；站点构建时按标题自动合并引用数。**抓不到数据时脚本不会覆盖旧文件**，所以失败了站点上的数字保持原样，不会归零。

平时不用手动点：[`.github/workflows/update-citations.yml`](../.github/workflows/update-citations.yml) 每天 03:00 UTC 自动跑一次。

> 中台里的「立即同步」是在**你本机**跑的，能出网就能成功；沙箱或代理环境下可能抓不到 scholar.google.com，日志里会写明。

## 四、备份与回滚

侧栏 → **备份与回滚**。

每次保存前自动留一份 `data/backups/content-YYYYMMDD-HHMMSS.json`，只保留最近 30 份。回滚的时候会先把**当前**内容也存一份，所以点错了还能救回来。

`data/backups/` 已被 gitignore，只是本机保险，不会进仓库。

## 五、加字段 / 改选项

字段定义集中在 **`admin/schema.mjs`** 一个文件里：中台表单、保存校验、侧栏计数都读它。

加一个字段，只要往对应分区的 `fields` 里加一行：

```js
{ key: 'doi', label: 'DOI', kind: 'text' },
```

`kind` 可选：`id` / `text` / `textarea` / `l10n`（双语单行）/ `l10ntext`（双语多行）/ `number` / `list` / `tags` / `select`。加了之后中台表单会自动多出这一项，不用改别的地方。

改选项（比如给「摘要语言」加一种语言）也是改这里。

> **注意**：校验遇到 `select` 里不认识的取值会**原样保留并提醒**，不会静默删除字段。

### 加一个分区

新加一个分区（比如「追踪卡片」）要动三处，漏掉任何一处都会出问题：

1. `admin/schema.mjs` —— 加进 `ORDER`、`COLLECTIONS`，并在 `ID_PREFIX` 里给它一个前缀。
2. `admin/lib/content.mjs` 的 `normalizeSection()` —— 如果用了新的 `kind`，**必须在这里补一个 `case`**，
   否则字段会被 `default` 静默丢掉（保存后才发现内容没了）。
3. `constants.ts` —— 从 `content.json` 读出给站点用。

> **关键**：`content.mjs` 的落盘函数只写 `ORDER` 里列出的分区。
> 往 `content.json` 里手动加了新分区却没写进 `ORDER`，**下一次在中台保存时会被整体删掉**。

## 六、出问题了

**页面打不开 / 端口被占用。**
换个端口：`npm run admin -- --port 4400`。

**保存被拒绝，提示「以下分区会被清空」。**
这是护栏：原来有内容的表变成了空数组时会拦一下，防止误清空。确认要清空就再点一次「确认清空并保存」。

**ORCID 拉取报错。**
检查 `admin/config.json` 里的 `orcidId` 是不是 `0000-0000-0000-0000` 这个格式。ORCID 公共接口不需要 token，报错一般是 iD 写错或网络不通。

**引用同步抓不到数据。**
`scholar.google.com` 对自动化访问有限制。脚本失败不会破坏数据；可以多试几次，或在 `scripts/update_scholar_citations.py` 环境里配 `SCRAPERAPI_KEY` 走代理。

**中文没显示成英文。**
双语字段只填了一边时，另一边会用同一边兜底，所以英文站上会显示中文。需要真正的英文就去对应条目的 `EN` 输入框补上。

## 七、边界

- **中台只在本机跑。** 需要 `npm run admin` 起着才能编辑；关掉终端就没了（数据都在文件里，不会丢）。
- **推送依赖你的 git 凭据。** 中台只是替你敲 `git commit` / `git push`，认证还是用你本机已有的配置。
- **引用数是异步的。** 抓取失败时站点显示上一次成功的值，不会变成 0 或空白。
- **`data/content.json` 可以手改**，但要保持结构：`id` 唯一、双语字段写成 `{zh, en}`。手改完刷新中台就会读到新内容。
