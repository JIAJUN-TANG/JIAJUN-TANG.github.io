这篇文章记录这个主页的搭建过程。

# 起点：模板撑不住了

最开始我用的是一个开源的学术主页模板[academicpages](https://github.com/academicpages/academicpages.github.io)。它把个人信息、论文、经历都写在配置文件或者`markdown`文件里，作为常量导出。对“填一次就不动”的主页来说，这很appropriate。

1. 问题是我想改的东西越来越多，论文要加中文摘要、经历要分学习/项目/会议、界面要中英双语、还要给不同学校配校徽。等到某一次我要改一条会议论文的作者顺序、却发现得去翻一个上百行的配置文件时，我意识到问题不在模板，而在**数据和代码混在一起**。
2. 这个前端已经多年未有更新，虽然对于学术主页来说合情合理，但少了一些个性和美。

我要的东西其实很简单：

1. 内容用**数据**的形态存在，改内容不需要碰逻辑；
2. 改内容的过程要有**校验**，别让我写出一个把站点搞崩的文件；
3. 数据要能**自动更新**的部分就别手动抄（比如引用数）；
4. 好看、个性、自定义程度高。

# 技术栈

前端没有花哨的东西：

| 部分 | 选择 | 理由 |
|---|---|---|
| 构建 | Vite | 快，配置少 |
| 框架 | React 19 + TypeScript | 类型能挡掉一大半低级错误 |
| 样式 | Tailwind CSS | 改样式不用跨文件跳 |
| 动效 | framer-motion | 标签切换、卡片入场 |
| 设计 | iOS26 Liquid Glass | 现代、美观 |

整体是**纯静态**的：没有服务端，没有数据库，构建产物就是几个文件，扔到`GitHub Pages`即可。这是刻意的——一个个人主页不值得维护任何后端。

# 数据放在一个 JSON 里

现在所有结构化内容都在 [`data/content.json`](https://github.com/JIAJUN-TANG/JIAJUN-TANG.github.io/blob/main/data/content.json)，分九个区：

- 论文、学术会议、科研项目
- 学习经历、荣誉奖励、学术著作、系统开发
- 首页动态、追踪卡片

`constants.ts`只负责读它，再做一点派生（比如首页的“教育与经历”直接从学习经历里筛出学位条目，避免同一段经历要维护两份）。

需要双语的地方，字段写成一对：

```json
{
  "title": {
    "zh": "人工智能技术驱动下海外中共党史资料整理与数据库建设",
    "en": "AI-Driven Compilation and Database Construction of ..."
  }
}
```

界面上切换语言时，`tr()`就是按当前语言取值，缺哪边就fallback到另一边。

# 如何更新数据：本地中台

一开始我的方案其实更“现代”：内容放**飞书多维表格**，用一个定时任务同步进仓库。听起来很优雅，甚至在手机上都能更新个人信息。

实际做下来发现成本全在看不见的地方：

1. 要建自建应用、申请`bitable`权限、**发布应用**（不发布读不到数据）；
2. 密钥要进`GitHub Secrets`，还得祈祷它不过期；
3. 双语字段在表格里要占两列，“XX（中）”/“XX（英）”，改一条论文要横着看半天；
4. 表格的高级权限一旦配错，接口会**成功返回空数组**，其后站点会被静默清空。

第4条是我最不能接受的：一个“正常返回”的错误，代价是整站内容消失。

我的内容总量也就三十几条，一年改几十次。为这个规模养一套复杂工作流，明显不划算。

于是换了个方向：**把中台跑在自己电脑上**。

```
浏览器表单  ──▶  admin/server.mjs  ──▶  data/content.json  ──▶  站点构建
                （校验、备份、git、ORCID、BibTeX一条龙服务）
```

`admin/`是一个纯Node的小服务，**零第三方依赖、没有构建步骤**，只监听`127.0.0.1`。用法就一条命令：

```bash
npm run admin     # 打开 http://127.0.0.1:4399/
```

跑起来之后：

- 左边选分区，点条目展开就是表单，改完 `⌘S` 保存；
- 保存流程固定为 **校验 → 备份 → 更新**。校验不过不写文件，保证安全性；
- 每次保存前自动留一份快照（保留最近30份），改错了能一键回滚；
- 顶栏直接「提交」「推送」，不用回终端敲git。

# 论文信息让它自己更新

论文这块手动抄最烦，能自动的都自动了。

**ORCID → 补全元数据。** ORCID的公共接口不需要任何token，用DOI检索、标题归一化回滚的方式跟站内论文配对。关键约束是：**只补空缺字段，不会覆盖手填内容**。你手写的摘要、备注不会被接口返回的东西冲掉。

**Google Scholar → 引用数。** 引用数变化频繁，交给一个脚本抓取，写进`data/scholar.json`；站点渲染时按标题合并。这个脚本由`GitHub Actions`每天自动跑一次。抓取失败时同样**不覆盖旧文件**，所以页面上显示的是上次成功的数字，不会变成0。

**BibTeX → 新增论文。** 中台里内置了一个解析器，能处理嵌套花括号（`{Immersion}`）、`\textit{}`、`\&`，也能把`Tang, Jiajun`转成`Jiajun Tang`，按DOI或标题自动去重。

# 部署

推送到`main` 分支，`GitHub Pages`自动构建。就这么多。

因为构建产物是纯静态的，本地`npm run build`出来的`dist/`和线上完全一致，出问题很好定位也方便预览。

# 每天怎么用

改一条论文的完整流程：

```bash
npm run admin          # 起中台
# 浏览器里改内容 → 保存（⌘S）
# 顶栏「提交」→「推送」
```

写一篇新博客：在`blog/`目录下新建一个`.md`文件，开头写一小段头部信息，正文随便写：

```markdown
---
title: 标题
date: 2026-09-13
summary: 一句话摘要
tags: [标签一, 标签二]
---

正文……
```

保存后刷新就出现在博客列表里——不用改任何代码，也不用维护目录文件。

也可以直接在中台中新建博客。
